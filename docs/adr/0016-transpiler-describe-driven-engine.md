# 转译补齐:describe 驱动通用引擎 + 代码生成器(落地 ADR-0005 后补路径)

架构落地(2026-08-12):ADR-0005 将"从 ccxt 转译批量补齐适配器"列为精选集之后的后补路径,ADR-0013 规定新增交易所按 HttpCore 深模块 + 四接缝(describe/sign/handle_errors/字段映射)。本轮将该路径落地为可重复执行的工具链:`scripts/gen_adapters.py` 从 vendored ccxt 4.5.73 的 `describe()` 抽取每个交易所的元数据(`id`/`name`/`version`/`rateLimit`/`has`/`api` 端点树/`fees.trading`/`timeframes`/`dex` 标志),生成 `&'static ApiSpec` 静态数据 + 一个经 `impl_generated_adapter!` 宏转发 16 个通用 REST 方法的轻量新类型;`generic.rs` 持有 `GenericExchange` 描述驱动引擎,以 `find_first()`(候选键词边界/token 匹配,含 `get`+名词前缀)+ `fill_path()`(`{param}` 模板替换)+ HMAC-SHA256 默认签名(`apiKey`/`sign`/`timestamp` 头,对齐 ccxt 基类)实现 ccxt 公共 REST 方法面,无法通用覆盖的方法继承 trait 默认 `NotSupported`(与 ccxt 行为一致);字段解析为 best-effort(多形状 fallback,所有响应保留 `info` 原始负载)。生成的适配器只填 describe 接缝(`ApiSpec` 即描述),sign/handle_errors/字段映射由通用引擎共享实现——这正是 ADR-0013 四接缝在批量场景下的体现。**覆盖结果**:转译生成 95 个适配器(79 CEX + 13 DEX + 3 预测市场),跳过 10 个已手写精选手写集(binance/okx/coinbase/bybit/bitget/kraken/gate/mexc/htx/kucoin,其非标准认证/字段已由手写保证精确性);hyperliquid 因全 REST 面为单一 `info` RPC(`{"type":...}` 体,无标准端点树)无法由描述驱动引擎路由,按 ccxt `hyperliquid.py` 手写公共行情面(markets/tickers/ohlcv/order_book,swap+spot);预测市场 kalshi/polymarket/manifold 已手写(ccxt.pro,不在 sync 集),而 `ccxt.prediction` 命名空间的长尾预测市场 limitless/myriad/opinion 通过扩展转译器(消费 `ccxt.prediction` 的 `describe()`)一并生成。合计 109 个适配器 = 全部 108 个 ccxt 唯一交易所/预测市场(103 sync 交易所含 89 CEX + 14 DEX,及 7 个 prediction 命名空间,binance/hyperliquid 双列)+ 1 个原生 Manifold,实现"接入所有 exchange/dex/预测市场"。**精确性边界**:转译适配器是 best-effort 批量补齐(ADR-0005 既定),默认签名仅覆盖 HMAC 类交易所;RSA-PSS/JWT/ECDSA/自定义头(如 okx/binance/kalshi/polymarket)仍由手写集覆盖;交易/持仓/余额等需特殊签名的私有面在转译适配器中为 `NotSupported`,以差分测试兜底的精确性由精选手写集保证。`gen_adapters.py` 幂等改写 `[features]`:追加每交易所 feature + `generated` 组 + 将 `generated` 并入 `full`。

- **Status**: accepted

**实施注记(2026-08-12)**:已完成工具链与全量生成。关键修复:(1) ccxt 4.x 端点值多为 `{cost:N}` 字典(路径即 key),`walk_api()` 据此取 path_val,否则 0 端点(最初 bitfinex 全跳过);(2) ccxt 4.x 动词为小写(`get`/`post`),`VERBS` 已含小写故正常,但 `key_matches` 须支持 `get`+名词命名(bitflyer `getticker`、independentreserve `getorderbook`),新增已知动词前缀匹配,同时保证 `openorders` 不误匹配 `orders`(`open` 不在前缀集)、`allorders` 不误匹配 `orders`(`all` 已从前缀集移除);(3) `rust_str` 改用 `ensure_ascii=False`,避免 `\uXXXX`(Rust 需 `\u{XXXX}`)非法转义导致全量编译失败(`binanceusdm` 名含 `\u24c8`);(4) HMAC 需 `hmac::KeyInit` trait(`new_from_slice` 在 hmac 0.12 移入 `KeyInit`);(5) `to_float` 容忍分层费率(`fees.trading.taker` 为 list/dict,hyperliquid 等最初因此 `describe` 报错);(6) `Timeframes::contains` 改为 `.iter().copied()` 避免 `&str`/`str` 比较。验证:`cargo build --all-features` 零错误零警告,`cargo clippy -D warnings` 全绿,`cargo test --all-features` 131 lib + 6 generic + 57 集成 + 5 fixtures + 1 realtime 全过(新增 generic 单元测试 5 例覆盖 key_matches 与解析)。hyperliquid 仅实现公共行情面,下单/撤单/持仓/余额需 L1 action 签名(EIP-712)+ agent 钱包,属独立大工作量,留作后续 curated 扩展,不在自动转译范围,已在模块文档中明示 `NotSupported`。(7) ccxt 4.5.x 大量端点值为 `1`/`True`(而非路径字符串或 `{cost:N}` 字典),含义为"路径即端点名(key 本身)";`walk_api()` 原仅处理 str/dict 值,会丢弃全部 `1` 值端点导致 0 端点被跳过(典型如 opinion),现统一为:值为字符串时取显式路径,否则取 key 为路径。此修复同时补齐了此前被漏抓的 `1` 值端点,transpiler 现额外覆盖 `ccxt.prediction` 命名空间(limitless/myriad/opinion)。
